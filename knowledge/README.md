# RAG knowledge base (for the reflect stage)

Grounds `reflect.py`'s optimization-instruction generation in curated fix recipes and the
official a14y docs, instead of relying on the model's memory alone.

## Layout

| Path | Content |
|---|---|
| `catalog.json` | One entry per a14y check id: `name` / `group` / `scope` / `priority` / `unlocks` |
| `checks/<id>.md` | **Curated, hand-written fix recipes** (frontmatter + body). Highest quality — used first. |
| `docs/<id>.md` | **Official a14y reference** per check, generated by `fetch_a14y_docs.py`. Fallback when no curated recipe exists. |
| `examples/` | Verified historical prompts (frontmatter `check_ids` / `score_before` / `score_after` / `verdict` / `final_score`) for semantic recall via `rag.rank_examples()`. |

## Recipe format (`checks/<id>.md`)

```markdown
---
id: <check-id>
name: <check name>
group: <group>
---

## What it checks
...

## How to fix
... (with a copy-pasteable snippet)

## Gotchas
- ...

## Acceptance
- `<check-id>` flips fail → pass.
```

The `rag.py` loader strips the frontmatter, so callers get a clean markdown body.

## Example format (`examples/<name>.md`)

```markdown
---
check_ids: ["llms-txt.exists", "html.json-ld", ...]
score_before: 30
score_after: 67
verdict: PASS      # optional; "PASS" examples are boosted by rank_examples
final_score: 76.57 # optional
---

<the full prompt.txt body that produced this result>
```

`rag.rank_examples` parses the frontmatter and multiplies the BM25 score of `verdict: PASS`
examples by a boost factor, so verified successes outrank unverified drafts.

## Retrieval precedence

For each fail / warn / error check id, `rag.retrieve_for_checks` returns:

1. `checks/<id>.md` if present (curated),
2. else `docs/<id>.md` if present (crawled),
3. else nothing (the check is skipped).

## Regenerating the docs

```bash
python fetch_a14y_docs.py            # fetch all checks in catalog.json
python fetch_a14y_docs.py --limit 5  # smoke test
python fetch_a14y_docs.py --force    # overwrite existing docs
```

Docs are keyed to the scorecard version in `catalog.json` (`scorecardVersion`); bump it and
re-run the crawler when a14y releases a new scorecard.
